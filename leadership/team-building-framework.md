# Building High-Performing BI Teams: A Framework

*Based on 3+ years of experience building and leading analytics teams*

---

## Overview

This framework outlines the approach I've used to build Business Intelligence and Analytics teams from scratch across multiple organizations. It covers recruitment, onboarding, team culture, and continuous development.

---

## Phase 1: Foundation (Weeks 1-4)

### Define Team Structure & Roles

**Squad Composition**
```
BI/Analytics Engineering Team (Typical Structure)
│
├── Analytics Engineers (2-4)
│   ├── Senior Analytics Engineer
│   ├── Analytics Engineer
│   └── Junior Analytics Engineer
│
├── Business Intelligence Analysts (1-2)
│   └── BI Analyst
│
└── Team Lead (You)
    ├── Technical Leadership
    ├── People Management
    └── Stakeholder Management
```

**Role Definitions**
- **Analytics Engineer:** Owns data transformation, modeling, and data product development
- **BI Analyst:** Owns visualization, stakeholder enablement, and ad-hoc analysis
- **Team Lead:** Owns strategy, roadmap, team development, and stakeholder relationships

### Establish Team Mission & Values

**Mission Statement Example:**
> "Empower [Company] teams to make data-driven decisions by providing reliable, accessible, and actionable analytics through modern data stack and exceptional stakeholder partnership."

**Core Values:**
1. **Quality over Speed** - We build things right, not just fast
2. **Documentation as Code** - If it's not documented, it doesn't exist
3. **Stakeholder Partnership** - We're business partners, not order-takers
4. **Continuous Learning** - We invest in growth and knowledge sharing
5. **Transparency** - We communicate openly about capacity and priorities

## Phase 2: Recruitment (Weeks 2-8)

### Job Description Framework

**Key Components:**
```markdown
# [Level] Analytics Engineer / BI Analyst

## About the Role
[Compelling description of impact and opportunity]

## What You'll Do
- Build data models using dbt and SQL
- Partner with stakeholders to define analytics requirements
- Create dashboards and reports in [BI Tool]
- Implement data quality checks and monitoring
- Contribute to analytics best practices and standards

## What We're Looking For
Technical Skills:
- Strong SQL proficiency (required)
- Experience with dbt (preferred) or willingness to learn
- BI tool experience (Tableau/Looker/etc.)
- Understanding of dimensional modeling

Soft Skills:
- Stakeholder communication and management
- Problem-solving and analytical thinking
- Documentation and knowledge sharing
- Agile/iterative development mindset

## Tech Stack
[List your stack]

## Growth Opportunities
[Career progression, learning, impact]
```

### Interview Process

**Stage 1: Screening (30 min)**
- Resume review and career trajectory
- Motivation and culture fit
- High-level technical discussion

**Stage 2: Technical Assessment (Take-home or 60 min)**
- SQL problem solving
- Data modeling scenario
- Dashboard design exercise
- Code quality and documentation

**Stage 3: Stakeholder Simulation (45 min)**
- Present findings to mock stakeholder
- Handle ambiguous requirements
- Prioritization discussion
- Communication skills assessment

**Stage 4: Team Fit (30 min)**
- Meet the team
- Culture and values alignment
- Questions about team dynamics
- Day-to-day collaboration style

**Stage 5: Final Interview (30 min)**
- Career goals and development
- Compensation and expectations
- Offer discussion

### Evaluation Criteria

**Must-Haves:**
- Strong SQL fundamentals
- Clear communication skills
- Problem-solving ability
- Growth mindset

**Nice-to-Haves:**
- dbt experience
- Specific industry knowledge
- Advanced statistical skills
- Programming (Python/R)

## Phase 3: Onboarding (Weeks 1-12)

### Week 1: Foundation
**Day 1-2:**
- [ ] Team introduction and welcome
- [ ] Access setup (GitHub, Snowflake, BI tools, Slack, etc.)
- [ ] Overview of company and business model
- [ ] Team mission, values, and ways of working
- [ ] Assign onboarding buddy

**Day 3-5:**
- [ ] Technical stack overview
- [ ] Data architecture walkthrough
- [ ] Key data sources and domains
- [ ] Documentation tour (Confluence, dbt docs, etc.)
- [ ] First small task (update documentation)

### Week 2-4: Technical Foundations
- [ ] dbt fundamentals training
- [ ] SQL best practices session
- [ ] Data modeling principles
- [ ] BI tool training
- [ ] Git workflow and code review process
- [ ] First code contribution (simple model or fix)

### Week 5-8: Domain Knowledge
- [ ] Business domain deep-dives
- [ ] Stakeholder landscape mapping
- [ ] Key metrics and KPIs overview
- [ ] Dashboard catalog tour
- [ ] Shadow stakeholder meetings
- [ ] First stakeholder interaction

### Week 9-12: Ownership
- [ ] Assigned domain area or project
- [ ] First end-to-end data product
- [ ] Lead stakeholder meeting
- [ ] Present work to team
- [ ] Onboarding feedback session

### Onboarding Checklist Template
```markdown
## Technical Setup
- [ ] GitHub access

- [ ] BI tool access

- [ ] Read team documentation
```

## Phase 4: Team Culture & Operations

### Regular Ceremonies

**Daily (15 min)**
- Team standup
- Blockers and support needs
- Celebration of wins

**Weekly (60 min)**
- Sprint planning or backlog refinement
- Technical deep-dive or learning session
- Code review sessions

**Bi-weekly (30 min per person)**
- 1-on-1 coaching sessions
- Career development discussions
- Feedback and growth

**Monthly (60 min)**
- Team retrospective
- Process improvements
- Stakeholder feedback review

**Quarterly (2-3 hours)**
- Roadmap planning
- OKR setting
- Team offsite or team building

### Communication Norms

**Slack Guidelines:**
- Use threads for discussions
- Tag appropriately for urgency
- Document decisions in Confluence
- Celebrate wins publicly

**Meeting Guidelines:**
- Always have agenda
- Document action items
- Recording for async review
- Required vs optional attendees

**Code Review Guidelines:**
- Review within 24 hours
- Constructive feedback
- Explain the "why" behind suggestions
- Approve if minor comments

## Key Success Factors

### What Makes BI Teams Successful

1. **Clear Mission & Priorities** - Everyone knows what we're building and why
2. **Strong Technical Foundation** - Modern stack, good practices, quality code
3. **Stakeholder Trust** - Built through reliable delivery and partnership
4. **Continuous Learning** - Investment in team growth and development
5. **Psychological Safety** - Team can ask questions, admit mistakes, take risks
6. **Work-Life Balance** - Sustainable pace, respect for boundaries
7. **Recognition & Growth** - Celebrate wins, provide development opportunities

### Common Pitfalls to Avoid

1. **Being order-takers** - Partner with stakeholders, don't just execute
2. **Neglecting technical debt** - Schedule time for improvements
3. **Poor documentation** - Make it a priority from day one
4. **Lack of prioritization** - Can't do everything, focus on impact
5. **Isolation from business** - Embed in business teams, build relationships
6. **Burnout culture** - Sprint is not a sustainable pace
7. **Unclear expectations** - Set clear goals and success criteria
